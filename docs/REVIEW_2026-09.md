# Codebase & Documentation Review — September 2026 (fourth pass)

Review of the full repository at `afce91b` (2026-09-24) for **currency, correctness,
consistency and compactness**, plus a survey of the current state of the art for
browser-based Codenames-style party games. Additive to the three earlier ledgers
(HARDENING_PLAN, IMPROVEMENT_PLAN, CODEBASE_REVIEW_PLAN); item ids here are `R*`.

**How to read this document.** Every finding was verified against the code on disk
(file:line given). Status markers are the source of truth; update them in the PR
that closes an item. "Unverified" marks a finding whose failure needs a condition
we could not reproduce here (e.g. Upstash's Lua null-drop, Redis Cluster).

## 1. Code findings

### 1.1 Security

| ID | Sev | Finding | Fix |
| -- | --- | ------- | --- |
| **R1** | High | **Host `sessionId` broadcast to every peer.** `room:joined`, `room:resynced`, `room:reconnected` emit the raw `Room` record, which carries `hostSessionId` (`types/room.ts:60`; `roomMembershipHandlers.ts:164`, `roomSyncHandlers.ts:61`, `roomReconnectionHandlers.ts:256`). Violates the N1 invariant ("peers see only the derived `playerId`"). The client never reads it (`grep hostSessionId src/frontend` → 0). Consequences: `GET /api/replays` authorizes on an `X-Session-Id` header alone (`replayRoutes.ts:62`), so any peer can act as the host there; and once the host's `session:auth` secret expires (fixed 24 h TTL, refreshed only on create/join/reconnect, `player/sessionAuth.ts:42-58`) while the player record keeps being refreshed by `atomicRefreshTtl.lua`, `resolveSessionId` falls back to the IP-only legacy check, so a same-NAT peer can adopt the host session. | Project the room before emitting (`hostSessionId` → `hostPlayerId = derivePlayerId(...)`) at the three peer-facing sites; `room:created` goes only to the host and may keep it. Refresh the auth-secret TTL wherever the player TTL is refreshed. Add a regression test asserting no `sessionId`-shaped field in any room broadcast. |
| **R2** | High | **Admin password check is unthrottled on `/health/metrics`, `/health/metrics/prometheus`, `/api-docs`.** `app.use('/health', healthRoutes)` (`app.ts:304`) and `app.use('/api-docs', basicAuth)` (`:309`) have no limiter; `apiLimiter` is mounted on `/api` only. Every request runs a full scrypt derivation (`utils/adminPassword.ts:52-60`) → unbounded online brute force of `ADMIN_PASSWORD` and a cheap CPU-exhaustion vector. `/metrics` and `/admin/*` are correctly limited. | Apply `strictLimiter` to `/health/metrics*` and `/api-docs` (same pattern as `app.ts:342`). |
| **R3** | Med | **Static `public/admin.html` is served unauthenticated** by `express.static` (`app.ts:294-300`); only the `/admin` route path is guarded. The page's API calls still need the password, so exposure is the UI shell only. | Exclude `admin.html` from static serving or serve it from the guarded route. |
| **R4** | Low | **Two humans can hold one team's spymaster seat.** `setRole.lua:43` ignores *disconnected* seat holders; when the first reconnects both have the key. Deliberate for the bot stand-in case, but `evictStandInBotIfAny` only evicts bots. | Either block the second human while a disconnected human holds the seat (within the grace window), or demote the returning one to clicker with a `room:warning`. |

### 1.3 Robustness (stated invariants not held)

| ID | Sev | Finding | Fix |
| -- | --- | ------- | --- |
| **R17** | Med | **Lock budgets shorter than inner operations (P0-3 invariant).** `withLock` runs `fn` under `lockTimeout − 500 ms`; on timeout the lock is released while the Redis write can still commit → no broadcast, clients desync. Violations: `submitClue` (getGame 10 s + eval 10 s in a 15 s lock); forfeit/abandon/pause/resume/finalize (`executeGameTransaction` = WATCH+GET+TTL+EXEC × up to 3 attempts in 15 s); `gameActions.ts:73-77` wraps `revealCard` in 10 s, *shorter* than lock-acquire + eval; `playerRoleHandlers.ts:110,183,284` 5 s around 4–5 Redis ops + a 10 s mutex; `botService.ts:51` 5 s around 5–7 ops. Bites only when Redis stalls, which is the case the invariant exists for. | Size each `lockTimeout` as the sum of inner budgets (the disconnect/timer paths already do); make the outer `withTimeout` in `applyReveal/applyClue/applyEndTurn` ≥ the inner lock budget. Fix the CLAUDE.md lock table at the same time (R40). |
| **R18** | Med | **WATCH/MULTI on the single shared connection is not isolated.** Redis WATCH state is per connection; `executeGameTransaction` (`luaGameOps.ts:302-383`) and the `playerService.ts:178-215` fallback run on the one `redisClient`. B's `EXEC` clears A's watch (optimistic lock silently gone); a modification to B's key (even `atomicRefreshTtl`'s EXPIRE) aborts A's EXEC → spurious `concurrentModification` after 3 retries. Exposure is limited because game writers serialize on `lock:reveal`, but pause/forfeit/abandon/finalize across many rooms under load can fail spuriously. | Run WATCH transactions on a dedicated/duplicated client, or move forfeit/abandon/pause/resume/finalize into Lua like the other ops (preferred: fewer moving parts, and it closes R17 for those paths). |
| **R19** | Med | **Removed bot can still land one move.** `botMayStillAct` runs only inside `if (pace > 0)` (`botController.ts:693-704`), so in `NODE_ENV=test` (pace 0) the whole pre-apply window (config read, up to 3 LLM calls ≈ 24 s, prewarm) is unverified; in prod the check precedes `applyClue/applyReveal/applyEndTurn`, which do no actor validation (`gameActions.ts:41-150`), and `removeBot` takes no lock. | Call `botMayStillAct` unconditionally immediately before apply; take the `bot-manage:` lock in `removeBot` and hold it in the controller around apply. |

## 4. State of the art (2025–2026) and ideas worth considering

Sources are listed in §4.4. Effort: S ≤ 1 day, M ≤ 1 week, L > 1 week.
**[ROADMAP]** = already in FEATURE_ROADMAP.md; **[EXISTS]** = partly present.

### 4.1 What the field looks like

- **Official Codenames Online** now runs *Codenames Daily* (four hand-picked,
  player-created puzzles per day, en/fr/es/de, same puzzle for everyone) and the
  App/Steam version offers **asynchronous** play (24 h per turn) and themed
  expansion packs. Pictures and Duet are first-class.
- **Recent open-source clones** (Cipher/mchen04 on PartyKit, codenames-double-agent,
  Clonenames) compete on *configurable rules* (YAML-defined modes, 3–4 teams,
  board sizes, extra assassins, hidden roles), **stackable themed word packs**
  (Cipher: 11 packs, ~2k audited words), colour-blind tiles (colour + pattern +
  label), team chat, and link-first joining. Horsepaste remains the reference
  minimal clone and now has an MCP wrapper so agents can play it.
- **AI**: Codenames is an established LLM benchmark (IEEE ToG 2025; GEM@ACL 2025
  where the best model won only 49 %; ACL 2026 "Concept" findings where no LLM
  passed 40 % and performance fell further in fr/es; the NeurIPS 2025 MindGames
  arena). The **2026 CoG Codenames AI Competition winner** uses "LLM proposes,
  code predicts the teammate's guesses and gates the announced number" — the same
  design as Eigennamen's `clueDryRun.ts`. Teammate-adaptation research (ACE:
  UCB bandit over expert agents) and a CSCW 2024 study showing that opaque LLM
  clue assistance *hurts* team mental-model formation both point toward
  **legible, adaptive** assistance rather than stronger black-box bots.
- **Web platform**: Socket.IO is still 4.8.x (WebTransport transport,
  `tryAllTransports`); WebTransport reached Baseline with Safari 26.4;
  same-document View Transitions are Baseline; **Declarative Web Push** (Safari
  18.4+) needs no service-worker code; the Web Share API supports files. For a
  2–8 player turn-based game the consensus remains server-authoritative state
  over WebSockets (no CRDTs). Party games overwhelmingly punt voice to
  Discord/Zoom; Discord *Activities* (embedded-app SDK) are the low-cost way to
  live where the voice already is.
- **Live-ops**: the Wordle loop (one seeded puzzle a day + spoiler-free emoji
  result card) is the proven virality mechanic and CGE has copied it. Global
  ELO exists only on account-based platforms (BGA, Colonist).
